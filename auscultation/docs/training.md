# 训练流程与反馈方案（Training & Feedback）

> 配套文档:[`model_architecture.md`](./model_architecture.md)(三模块结构 + Target Hand-off 接口)、[`datasets_and_processing.md`](./datasets_and_processing.md)(感知数据)。
> 本文回答:**感知之后、3D 目标点交给 VLA 之后,反馈闭环怎么做、怎么用遥操作做模仿学习收数据、业界(尤其自动驾驶)怎么处理。**

---

## 0. 先破除最大的误区:三个 "loop" 不是一回事

| Loop | 在哪发生 | 是不是"训练时的反馈" |
|---|---|---|
| **A. 推理控制闭环**(sensorimotor loop)| 部署时, 策略以 f Hz 跑 | ❌ 是运行, 不是训练 |
| **B. 音频闭环**(模块③)| 部署时, 接触后精修落点 | ❌ 同上 |
| **C. 训练**(模仿学习 BC)| 离线, 在演示数据上 | ⚠️ **纯 BC 训练时没有 loop、没有 reward** |

**核心洞察:**
> **模仿学习 = "用开环的监督训练,学出一个闭环的策略"。** 训练时就是普通监督回归 `观测 → 动作`;反馈是**部署时**才通过**环境 + 传感器**闭合的,不靠训练信号。演示里的人类本身在做反应式行为(力小了就压、声音差了就挪),策略照着学 `观测→纠正动作` 的映射,闭环行为自然被学进去。

---

## 1. 部署时:反馈怎么闭合(sensorimotor loop)

3D 目标点**不是一次性丢给 VLA**。每个控制周期(~10–50 Hz)循环:

```
每一帧:
  相机 / 力 / 音频 / 关节 → 当前观测
  感知模块(每帧重跑)→ 更新 3D 目标点(病人动/视角变, 目标自动跟)
  VLA(吃: 第三人称图+目标热图, 腕部图, 3D点, 力, 音频, 本体, 语言)
      → 输出未来 K 步动作块(action chunk)
  执行动作 → 机械臂动 → 环境改变 → 下一帧
```

**"反馈" = 传感器:**
- **力**:接触了没 / 压够目标力没 → 逼近轻、接触稳;
- **音频**:声窗好不好 → 不清就在邻域挪(模块③);
- **视觉**:目标现在在哪 → 3D 点每帧重算, 病人动了目标跟着动。

**3D 点是"目标条件"(goal conditioning),不是控制信号**——它一直挂在输入上告诉策略"往哪去";怎么贴合、贴歪怎么纠由力/音频/视觉的实时反馈驱动。范式 = **goal-conditioned imitation learning**。目标点的解剖来源见 [`ausc/tasks.py`](../ausc/tasks.py)(task→点集)+ `define_ausc_vertices`。

## 2. Phase 1–2:遥操作 + 模仿学习收数据与训练

### 2.1 采集(主从臂遥操作 teleoperation)
- 人操作 **leader 臂**(或 VR 手柄 / SpaceMouse),**follower 臂**(真机)实时跟随;
- **同步、时间戳对齐**录:全部相机流 + 关节状态(本体)+ 6 轴力/力矩 + 听诊器音频 + 人下达的动作(leader 位姿/目标关节)+ 语言指令 + 任务(heart/lung);
- 参考系统:ALOHA / ACT(双臂遥操作)、π0 数据格式。
- 先在**人体模型/假人**上采集降低 IRB 压力, 再迁移真人。

### 2.2 训练对
| | 内容 |
|---|---|
| **输入(观测)** | 第三人称图(+目标热图)、腕部图、3D 目标点、本体、力/力矩、音频、语言、task |
| **标签(动作)** | 那一帧人**实际下的动作**:末端 6-DoF 位姿增量 或 关节目标 |
| **动作分块** | 一次预测未来 **K 步**(ACT / π0 都如此, 抗抖、抗误差累积) |

> **3D 目标点从哪来(实践要点)**:teleop 时可(a)在线跑感知出点, 或(b)更干净——**从这条演示的最终接触位姿反推 goal**(人把听诊器放哪儿哪儿就是目标), 再渲成热图+3D点当输入。这样**遥操作数据无需再标 IUV**(正是设计B 的好处)。

### 2.3 训练方法
- **行为克隆(BC)**:最小化"预测动作 vs 人的动作";
- **骨干 = π0**:PaliGemma 视觉-语言 trunk + **flow-matching** 动作专家(比纯 L2 更能拟合多模态动作分布), 吃 π0 大规模机器人预训练权重;
- 学的不是"到坐标", 而是"**逼近 → 接触 → 稳到目标力 → 听诊 → 按声音探索**"这套接触-力技能。

## 3. 纯 BC 的硬伤 + 怎么把"反馈"加回训练

> **协变量漂移 / 误差累积(covariate shift)**:测试时策略走到演示没覆盖的状态 → 犯小错 → 越漂越远 → 崩。这是纯 BC 的经典病。

补法(由轻到重, 也是我们的推进顺序):

| # | 方法 | 作用 | 何时上 |
|---|---|---|---|
| 1 | **Action chunking + 时间集成**(ACT)| 预测块+平滑执行, 大幅减累积误差 | **Phase 2 必上**(π0 原生)|
| 2 | **DAgger / HG-DAgger**(交互式纠正)| 策略先跑, 人在它要犯错时**接管纠正**, 干预数据=反馈信号, 回灌再训 | Phase 2 漂了就上 |
| 3 | **大规模多样化预训练**(π0 / RT-X / Open X-Embodiment)| 泛化好→不易漂 | 用 π0 预训练权重即享 |
| 4 | **RL 微调(真·反馈闭环)**| 在 BC 之上加**奖励**在线/离线精修 | **Phase 3** |

> **对我们,音频质量就是天然奖励**——这是差异化 C/D:系统从"声音好不好"这个反馈里学"该在哪听、怎么挪",涌现点定义。**这一层才是真正意义上的训练反馈闭环, 但必须建在 BC 打好的底子之上。不要一上来就 RL。**

## 4. 类比:自动驾驶怎么做反馈(结构几乎同构)

| 环节 | 自动驾驶 | 我们 |
|---|---|---|
| 感知(分开训, 监督)| 检测 / 车道 / 占据栅格 | 稠密 IUV |
| 策略(吃感知输出)| planner / 端到端控制 | VLA |
| 训练起步 | **模仿人类驾驶(BC)**:ALVINN、PilotNet、特斯拉/Waymo 早期 | teleop BC |
| 同样的病 | covariate shift(偏离车道不会回正)| 同 |
| 补①海量数据 | 车队学习(百万英里)| HuMMan/合成 + 多 demo |
| 补②**闭环仿真** | CARLA/Waymo 仿真里闭环跑、测发散(真路不敢闭环)| Isaac/仿真闭环评测 |
| 补③**接管=DAgger** | 安全员 **disengagement/接管** = 干预纠正数据 | HG-DAgger 人工接管 |
| 补④**World Model** | Wayve GAIA-1 / MILE:学世界模型在"想象"里闭环训练 | 差异化 C(声学 World Model)|

> **要义**:AD 也是**开环训练、闭环部署**;反馈靠"接管纠正(DAgger)+ 闭环仿真 + 世界模型"三件套加回训练。我们多了一条 AD 没有的反馈通道——**声音**,这是我们能超越"找点→执行"的关键。

## 5. 我们的训练路线图(落地顺序)

```
Phase 1  采集: 主从臂遥操作, 同步录 RGB-D+力+音频+本体+语言+task; 假人先行
   │
Phase 2  模仿学习(BC):
   │     π0 (PaliGemma + flow-matching), goal-conditioned(吃热图+3D点), action chunking
   │     → 漂移就上 HG-DAgger 人工干预回灌
   │
Phase 3  反馈闭环(差异化):
   │     B 音频闭环: 声音差→邻域 (I,U,V) 搜更好点
   │     C World Model: 学"声音随 (I,U,V)/力/呼吸 怎么变", 规划信息增益最大的下一点
   │     D 声音自监督定点: 奖励=声音质量, 自学"哪儿声音最好", 翻转"人找点机器执行"
   │
Phase 4  部署评测: 跨体型/坐姿成功率, 定位/力误差, 声音质量, 安全; vs 硬编码/Lopes/Zhu
```

- **感知与 VLA 分开训**, 只经 [`Target Hand-off`](./model_architecture.md) 接口(热图+3D点)耦合;遥操作数据不必标 IUV。
- **3D 点每帧重估** → 病人移动自动跟, 这是感知→策略的运行时反馈。
- 任务条件化(heart/lung/…)由 [`ausc/tasks.py`](../ausc/tasks.py) 路由, 决定调哪组点位/区域。

---

> 一句话:**开环监督训练(BC)学出闭环策略, 部署时靠力/音频/视觉传感器闭合反馈;协变量漂移用 chunking→HG-DAgger→audio-RL 逐级补;声音是我们独有的反馈通道。**
