# 自采肺音:标注 + 采集 + 训练协议（与 Q 模型 / 机械臂场景紧密贴合）

> 配套:[`acoustic_quality_strategy.md`](./acoustic_quality_strategy.md)(模块总纲 + §5 同步采集)、
> [`ausc/audio/proxies.py`](../ausc/audio/proxies.py)(S1 自监督代理)、[`model_architecture.md`](./model_architecture.md) ③(Q 在整机闭环里的角色)。
> 本文回答:我们将手动采集后背肺音来训练,**该怎么标注、怎么采、怎么训**,才贴合"机械臂自动听诊"这个落地场景。

## 0. 先纠一个最关键的概念:质量 ≠ 病理

你给的方案 2(「出现某种特定肺音信号才算好」)**是个陷阱**,必须先掰清楚:
- **质量 (quality)** = "这段录音清不清楚、能不能用来诊断"——和听到的是正常呼吸音还是 crackle/wheeze **无关**。
- **内容/病理 (content)** = "听到的是正常 / 湿啰音 / 哮鸣音 / 无呼吸音"——这是**诊断标签**,不是质量。

一段**干净的正常呼吸音**是高质量;一段**干净的带 crackle 的录音**也是高质量(而且诊断上更有价值);一段**嘈杂的录音**无论里面有没有 crackle 都是低质量。**Q 模型判的是质量,不是病理。** 把两者混在一个标签里,模型会学歪(把"安静的正常肺"误判成差)。

> ✅ 唯一的例外:**"有没有气流声(air entry)"是质量前提**——你得先听得到病人在呼吸,才谈得上质量。但"听到气流"≠"听到某种病理音"。

**所以:两条正交的标注轨道**——质量轨(喂 Q)和内容轨(喂将来的诊断模型),分开标、永不混。

## 1. 标注单元:以「呼吸周期」为原子,聚合到「一次落点」

回答你的三个方案:

| 你的方案 | 评价 |
|---|---|
| ① 固定 5s 窗,每 5s 判好坏 | **机制对一半**:部署时确实要滑窗实时监测,但 5s 是任意切的,可能切断一次呼吸。应**对齐呼吸周期**。 |
| ② 出现特定肺音才算好 | **❌ 概念错**:那是病理不是质量(见 §0)。质量 = 呼吸音清晰 + 低噪,与病理无关。 |
| ③ 用"几次跳动"作计数单位 | **✅ 方向对**:但单位不是心跳,是**呼吸周期**(吸气+呼气)。肺音天生按呼吸组织。 |

**推荐综合方案(三者合一):**
- **原子单元 = 一个呼吸周期**(inspiration + expiration)。肺音只在有气流时才有信息,呼吸周期是它的自然节拍(对应 ICBHI/HF_Lung 的逐周期标注)。一个成人周期 ~3–5s。
- **判定单元 = 一次落点(~10s 持留)**:机械臂在一个后背肺点(R1..L5)按住录 ~10s,含 ~2–4 个呼吸周期。**Q 真正要回答的是"这次落点录到的能不能用"** → 把周期级质量**聚合**成落点级好坏。
- **部署监测 = 滑窗(方案①的机制)**:实时跑一个 ~6s 滑窗(保证含 ≥1 完整周期),步进 ~0.5–1s,边录边判。

> **最贴合机械臂的洞见——停留策略用"凑够 N 个干净呼吸周期就走"(Q 门控自适应停留),而不是死等固定 10s。** 这正好把方案③当成**停留终止条件**:臂按住 → 实时数干净周期 → 凑够 N(如 2)个就抬走,否则到超时再判"差→换位/调力"。这还顺带缓解架构里"每点录音 ~10s"的速度瓶颈(好点可能 4–6s 就够,差点早点放弃)。

## 2. 标注轨道与字段(每次落点录音标这些)

### A. 质量轨(Q 的训练目标)—— 多维 + 序数
| 字段 | 取值 | 给谁用 |
|---|---|---|
| **overall_quality** | 0 不可用 / 1 勉强 / 2 好 / 3 优(序数;或用配对排序给连续分) | Q 主目标 |
| **clean_cycles** | 这段里**干净呼吸周期数**(含吸/呼) | 充分性 + 停留策略 |
| **air_entry** | 有/弱/无(听不听得到呼吸气流) | 质量前提 + 区分"没贴好"vs"真无呼吸音" |
| **failure_reasons**(多选) | 运动/摩擦伪影 · 环境噪声/说话 · 贴合差(闷/无气流) · 削波 · 心音主导 · 间歇掉接触 | **告诉机械臂"为什么差→怎么修"** |

`failure_reasons` 是把质量从"一个分数"变成"可执行信号"的关键——它直接映射到机械臂动作(见 §6),也用来校准/精修我们的自监督代理(每个 reason 对应 proxies.py 里一个指标)。

### B. 内容/诊断轨(单独,喂将来的诊断模型,**不进 Q**)
- 逐呼吸周期:normal / crackle(fine/coarse)/ wheeze / rhonchi / stridor / **absent**。对齐 ICBHI 的逐周期 crackle/wheeze 制式,便于迁移。
- ⚠️ **absent(无呼吸音)要打上下文标**:配合当时的"在不在肺点(感知)+ 力够不够(力反馈)"——若位姿/力都正常仍无呼吸音 → 可能是真临床发现(如积液);若接触/力不对 → 是质量失败。**这一步把音频标注和机械臂的本体感知绑在一起**(见 §3)。

## 3. 采集规范(贴合机械臂,产出"好标"的数据)

每条自采样本由遥操作/机械臂录制,**与 RGB-D / 力 / 语言时间戳严格对齐**(已在 strategy §5),并额外做到:

1. **呼吸相位参考信号(关键,且我们已经有)**:用**力反馈模块的 Hall 位移信号**当呼吸基准——被动弹簧托架会随胸壁起伏(2–5mm)上下浮动,Hall 位移**直接编码呼吸相位**(mechanical_sensor 文档里"控制器须 servo-track 呼吸"说的就是这个信号)。它给我们**免费的、已同步的呼吸周期真值边界**,用来:(a) 锚定周期级标注;(b) 训练/验证 `respiratory_periodicity` 代理;(c) 当停留策略的"数周期"计数器。可再用深度(胸廓位移)交叉验证。
2. **成对好/坏(by design)**:在**同一个后背点**故意录"好 vs 坏"——好接触 vs 太轻/太重、静止 vs 故意滑动、安静 vs 说话。**同点配对**控制住了解剖差异,把"质量"单独隔离出来——这是训 Q **最值钱**的数据技巧(见 §5 配对排序损失)。
3. **连续录整段持留**(不是只截一小段):录下臂从逼近→稳定→听诊的全过程,标注者能标"何时变好"(臂稳定后才好),也喂给停留策略学"多久能稳"。
4. **元数据随录**:task=lung、点名 R1..L5、目标力 & 实测力、Hall 位移序列、是否重录、操作者动作标签。manifest 一条一行(schema 见 strategy §5,扩展上面 A/B 字段)。

## 4. 标注流程(高效,别纯人工硬标)

1. **代理预标**:先用 S1 的 `Q_proxy`(已在 SPRSound 'Poor Quality' 上校准)给每段**自动打初分** + 每个失败维度的子分 → 标注者看到的是"预填好的表 + 波形 + 频谱图 + 同步视频",只需**确认/纠正**(active learning)。
2. **优先标"代理拿不准"的**:proxy 分在中段、或 proxy 与上下文(力/位姿)矛盾的样本,信息量最大,优先送人工。
3. **连续质量用配对排序**:绝对打分(MOS)主观、一致性差;**"A 比 B 清楚吗"**(尤其同点好/坏对)又快又一致 → 训练时转成 ranking 损失。少量锚样本定标尺。
4. **临床医生标定子集**:让医生在一个小集上判"够不够诊断级",锚定整把尺子的医学含义(我们不是音频工程师说了算)。

## 5. 训练流程(与 Q 架构对齐:冻结 OPERA + 轻头)

分两段,和感知模块"先开源 bootstrap、再自采 in-domain"完全同构:

**S2a — Bootstrap(开源 + 代理弱标,已在做)**
- 冻结 **OPERA**(呼吸专用编码器)→ 轻量质量头 → `Q∈[0,1]` + 不确定性。
- 监督 = S1 自监督代理弱标(主) + **SPRSound 'Poor Quality' 校准**(真质量标)。产出 **Q v0**。

**S2b — 自采 in-domain 微调(本文数据)**
- **多头轻头**:
  - `overall_quality` 头:序数回归(CORAL/ordinal)或回归到 0–1。
  - `failure_reasons` 头:多标签 BCE(辅助,且驱动机械臂动作)。
  - **配对排序损失**:同点 good/bad 对上 margin ranking(§3.2 的数据)——最稳的信号。
- **周期级 → 落点级聚合**:编码器逐呼吸周期出分(周期边界来自 §3.1 的 Hall 位移),再用 attention/mean 池化到落点级。好处:对"窗切在哪"鲁棒,且给**可解释的逐周期分**。
- **条件化本体感知**:把**力 + 在不在肺点(感知输出)**作为旁路输入喂质量头——Q 学的是"在这个力、这个位姿下,音频够不够诊断",这正是机械臂要的条件质量,也能区分 absent 的两种成因。
- **不确定性是一等输出**:MC-dropout/集成 → Q 低**或**不确定性高都触发探索(与感知翻转一致性置信门同构)。
- 切分**按受试者**;验证用医生标定子集 + 复测 SPRSound PQ AUC,防过拟合。

## 6. 与整机闭环的衔接(Q 不只是分数,是动作信号)

部署时(架构 ③ 的声音闭环),机械臂在一个肺点按住,实时滑窗跑 Q + failure_reasons:

```
按住肺点 → 滑窗 Q + 数干净呼吸周期(Hall 位移计数)
  ├─ Q 高 且 凑够 N 个干净周期 → 采纳, 抬走去下一个点(自适应停留, 比死等 10s 快)
  └─ Q 低 / 不确定 → 看 failure_reasons 决定动作:
       贴合差/无气流  → 加力(力反馈模块) 或 微调位姿
       运动/摩擦伪影  → 稳住/等臂静止后再录
       环境噪声/说话  → 等一下重录
       心音主导       → 沿体表(IUV 流形)往肺野中心挪一点
       到超时仍差     → 标 NEEDS REVIEW / 换邻近点(主动探索, 差异化 B/C)
```

这样 Q 把"听得清不清"翻译成"该加力 / 该稳住 / 该挪哪 / 该不该走",**质量模型直接驱动机械臂的搜索与停留**——这就是"流程与整个模型紧密贴合"的落点。

## 7. 一句话总结

> **标注单元用呼吸周期(方案③),聚合成一次落点的好坏 + 失败原因(质量轨),和病理诊断(内容轨)严格分开(否定方案②);部署用滑窗实时监测(方案①机制)、"凑够 N 个干净周期"作自适应停留。采集靠机械臂同步录音 + Hall 位移当呼吸相位真值 + 同点好/坏配对;标注靠代理预标 + 人工纠正 + 配对排序 + 医生定标;训练靠冻结 OPERA + 多头轻头(序数质量 + 失败原因 + 配对排序),周期级聚合 + 本体感知条件化 + 不确定性,最终 Q 直接驱动机械臂的加力/稳住/挪位/停留。**
