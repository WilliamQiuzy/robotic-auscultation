# 工程流程详解（Engineering Plan）

> 总览见 [../README.md](../README.md)。本文把每个 Phase 的工程细节展开，重点在 Phase 1 数据采集。

## 0. 核心认知：数据分两条轨道

整个项目最大的难点是数据。关键是想清楚**数据有两条独立轨道**，需求/规模/采集方式完全不同，绝不能混为一谈：

| | **感知轨道（Perception）** | **动作轨道（Action）** |
|---|---|---|
| 学什么 | 图像 → 听诊点位置 | 逼近/接触/调力/听诊/探索的运动技能 |
| 来源 | 网络人体图片 + 自动标注 | 主从臂遥操演示 |
| 产出 | 2D 点（+UV / 3D 法向） | 轨迹 + 力 + 音频 |
| 规模 | 百万级，便宜 | 百~千级，贵（真人受 IRB 限制） |
| 在线推理 | 快速前馈，**无需逐病人配准** | 策略 rollout |

> 配准/解剖图谱被**挪到离线训练**（在网图上做自动标注），换来**在线推理无配准、快、鲁棒**——这是差异化 A 的实现方式。

---

## Phase 0 — 硬件与标定（前置，必须最先做）

不依赖任何数据/IRB，是其它一切的物理前提。

- **末端连接件（3D 打印）**：把电子听诊器（如 Thinklabs One / Littmann CORE）固定到机械臂法兰。加**硬质泡沫**做声学隔离（Zhu 同款）。快拆设计。
- **力反馈**：两条路线——
  - (推荐起步) **弹簧被动机构 + 位移传感器**（Tsumura）：机械保证恒力，安全不依赖算法，便宜。
  - (进阶) 腕部 **6 轴力/力矩传感器** + 主动阻抗控制：力进观测空间，闭环可用。
- **标定**：手眼标定（相机→base）、F/T 零偏 + 重力补偿、听诊器尖端 TCP 偏移。
- **可达性分析**：用我们这把臂在桌面安装下做工作空间分析，决定病人**坐 / 躺**、听**胸 / 背**。⚠️ Lopes 的 UR3e 因桌面碰撞够不到下背部点——这是真问题，先验证。

## Phase 1 — 数据采集（最难的一段）

### 1A 感知轨道：用现成数据集 + 自动标注

> **✅ 感知定位模型已投产(2026-06-14)。** 三数据集生成 + 训练 + 评测 + 部署全打通。生产模型 = `perc_lmh_v4`(landmark 热图头 + 结构化读出),对人手金标 **PCK@10 ≈ 96%**(旧 IUV-地址法仅 57%)。代码 [`ausc/models/`](../ausc/models)+[`ausc/training/`](../ausc/training),部署 [`scripts/deploy_landmark.py`](../scripts/deploy_landmark.py);现状/演化见 [`PERCEPTION_STATUS.md`](./PERCEPTION_STATUS.md)、[`landmark_head_and_eval.md`](./landmark_head_and_eval.md)。下面 HuMMan/COCO 内容为过程记录。
>
> **HuMMan**（HuggingFace `caizhongang/HuMMan`，非门控）：受控影棚 + 稠密 SMPL 真值 + RGB-D + 1000人。
> 流水线 `ausc/humman_label.py`：SMPL参数→6890顶点→听诊点(模板按解剖比例选固定顶点)→相机投影→**精确 2D，不塌缩**。
> 依赖 `data/smpl/SMPL_NEUTRAL.pkl`（注册下载；v1.1.0 含 chumpy 需清洗：`pip install --no-build-isolation chumpy` + numpy别名补丁 → 转纯numpy）。
> **听诊点(当前标准, 2026-06)**：前胸=**5 个心脏点 APETM**(主动脉/肺动脉/Erb/三尖/二尖, Bates')；后背=**10 个肺点 V6A**(5 层双侧, 围肩胛骨, Lopes 谱系)。解剖定义在 `ausc/humman_label.define_ausc_vertices`,任务→点集 + landmark 通道顺序在 `ausc/tasks.py`。⚠️前胸点≠后背点(心 vs 肺,不同器官)。
> **前胸/后背判别**：稠密IUV躯干块 part2=前胸/part1=后背,谁多算谁(`ausc.humman_label.infer_side`,实测前87209:770/后544:45278,零歧义)；标注时用 `frame_filter.classify_frame` 路由。SMPL 标定：+x=患者左,-x=患者右,躯干核心|x|<0.16。
> **已做**：三数据集全量生成(~2.97万训练图,真实后背~6484,betas自适应体型) → landmark 头直接监督训练(纯人手标种子+自训练放量) → 金标评测 + 翻转一致性置信门部署。**后续**:更多人工多样真背破 96→98%;自采裸皮临床集 in-domain。

目标：海量 (图像, 听诊点) 数据，训练一个跨体型/姿态/着装都鲁棒的定位模型。

**两条结论（经调研）：**
1. 不存在「图像 + 听诊点」的现成标注数据集，必须自己标。
2. **临床视角 = 近距离躯干/背部特写**（参照 Lopes Fig.16/17：裸背特写、人充满画面），而非开放世界全身远景。按这个视角重排数据集，比单看标注丰富度更重要。

#### 数据集排名（按「视角匹配 + 标注可用 + 多样性 + License」综合）

| 排名 | 数据集 | 评价 | 用法 |
|---|---|---|---|
| 1 ⭐ | **DensePose-COCO（按躯干裁剪）** | 5万真实图 + 每像素 UV 手工标注。原图是全身远景，但**按躯干裁紧 → 当场变成近景躯干特写**，框架对上；UV 直接投影出听诊点，无需跑模型 | **主力**（可规模化） |
| 2 ⭐ | **自采临床集（机器人 RGB-D）** | 真分布、真近景、可裸皮——唯一完全对口的数据。三篇论文都自采 | 金标准 / 微调 / 验证（Phase 0/1 建） |
| 3 | **AGORA（人物 crop）** | 合成但 SMPL-X 真值绝对准，给 3D/法向监督 | 补 3D 监督 |

| 5 | BodyM（AWS） | 全身**黑白剪影**、缺皮肤纹理；站姿少衣分布尚可 | 边际可用，剪影做轮廓先验 |
| 6 | Human3.6M | 实验室、演员、多样性弱 | 备选，量大 |
| ~ | NTU-Nipple-v1 | 仅乳头锚点（Tsumura 用乳头定位） | 可训一个乳头检测器做锚点 |
| ✗ | 皮肤科（Fitzpatrick17k/SCIN/SkinCAP） | 皮损**特写**，无身体框架/解剖结构 | 剔除（仅可借肤色多样性做域随机化） |
| ✗ | 胸片（VinDr-CXR/NIH/PadChest） | X 光，非体表 RGB，模态错 | 剔除 |

#### 处理域差（近景特写）的三招

1. **躯干裁剪**：用 DensePose/关节框把全身图裁成躯干特写，把"全身远景"转成"临床近景"。
2. **尺度/裁剪抖动增强**：模拟相机远近、构图差异。
3. **自采小集 + 微调**：机器人 RGB-D 采几十~几百张真临床视角，做 fine-tune 和验证，弥补皮肤纹理域差。

#### 流程

1. **取数据**：以 **DensePose-COCO（躯干裁剪）为主**，+ AGORA/3DPW 补 3D 监督，+ 自采临床集做金标准。胸面（心脏点）+ 背面（肺点）。
2. **定义听诊点（一次性，hard-code 在模板上）**：每个听诊点 = **固定 DensePose UV 坐标**（和/或 SMPL 顶点）。这是唯一 hard-code，泛化交给人体模型。
3. **投影到每张图**：DensePose-COCO 已有 UV→直接投影；其它图源跑 DensePose/SMPL-X 预测器（4D-Humans/PIXIE）→投影。
4. **自动过滤**：置信度、可见性、躯干完整性、姿态合理性。坏样本直接丢（"能用就行"）。
5. **金标准校验**：人工标几百张算误差，够用即可。

⚠️ 此轨道**只解决定位**，给不了深度/力/音频/动作。机器人端有 RGB-D，2D 点反投影成 3D。
⚠️ DensePose-COCO 为 NonCommercial CC（科研可，商用需注意）。

#### 原型实测结论（已在 minival 跑通，见 `scripts/inspect_densepose.py`）

- ✅ **自动标注流程成立**：图 → DensePose UV → 按目标 (I,U,V) 最近邻 → 2D 听诊点。多张样图验证，点稳定落在胸前躯干。
- ✅ **躯干裁剪有效**：裁到 bbox 即得近景躯干特写，框架对上临床视角。
- ⚠️ **COCO 域差实锤**：真人是日常穿衣、拿瓶子/侧身等姿态，非规整正面医检姿；落点"大致在胸部"但需过滤正面/无遮挡躯干 → 更印证要补**自采临床集**。
- ⚠️ **临时 (I,U,V) 仅演示**：精确解剖定义待医学校验。
- 📌 **全量批标注**：稀疏 GT 最近邻仅适合有标注的 COCO 子集；对任意图（含机器人自采）需跑 **Detectron2 DensePose 预测器**输出逐像素 IUV。
- ✅ **正面/背面躯干过滤器**（`scripts/filter_torso.py`）：DensePose 前/后块比例 + COCO 双肩朝向佐证，分 front(→心)/back(→肺)/reject。minival 实测：2243 带标注人 → 正面 1554 / 背面 359 / 拒绝 330（侧身/冲突/点少）。

#### 已实现脚本与标定（Phase 1A 落地）

| 脚本 | 作用 |
|---|---|
| `inspect_densepose.py` | 检查标注 + 可视化 |
| `filter_torso.py` | 正面/背面躯干过滤器 |

**UV 坐标系（由 minival 反推，两个躯干块一致）**：`U`=垂直(0上→1下, corr≈0.60)；`V`=水平，**V 高=患者右、V 低=患者左、0.5=中线**（正/背面都成立 → 患者相对、解剖一致，这是固定 (I,U,V) 能跨人迁移的根基）。

**心脏点映射统计验证**（1554 正面人均值，nx:0图左/患者右→1图右/患者左，ny:0上→1下）：aortic(0.46,0.46 右上)、pulmonary(0.54,0.47 左上)、tricuspid(0.50,0.59 中下)、mitral(0.58,0.61 左下偏外) —— **符合标准心脏听诊布局**。

**批标注产出**：minival → 1913 标注样本（正面1554×5心脏点 + 背面359×6肺点），导出 `data/labels_minival.json`（格式见 `data/README.md`）。

⚠️ (I,U,V) 为医学草稿，待解剖合作者校验；侧身/遮挡靠过滤器筛，自采临床集补域差。
📌 backend=predictor（任意图/机器人自采）在 GPU 服务器跑 `densepose_predictor.py`，本机仅持代码。

### 1B 动作轨道：主从臂遥操演示

目标：教机器人**运动技能**（不是定位）。

- **遥操**：主从臂（leader-follower）或动觉示教（gravity-comp 手扶）。
- **每帧记录**：主/从臂关节角+速度、末端 6D 位姿、6 轴力/力矩（或弹簧位移）、RGB-D（腕部 + 可选外部）、**听诊器音频流**、语言指令、事件标记（接触起始/保持/回撤）。
- **时间同步**（关键工程难点）：音频高采样率（数 kHz）、控制 ~10–125Hz、相机 ~30Hz。需统一时钟 + 时间戳（ROS2 bag / LCM / 自研 logger），最好硬件触发。
- **演示协议**：标准化（home→点 i→接触到 F_target→保持 10s 录音→回撤→下一点）+ **探索式演示**（演示者根据听到的声音去搜索、左右对比）——后者才是闭环行为的来源。
- **降 IRB 压力**：先在**人体模型/假人**上采，再迁移真人。

### 1C 音频采集与标注

- **同步采集**：与 1B 轨迹严格对齐，只有"保持接触"那段有效，逼近/回撤是噪声。
- **标注**：部位、质量分（0–1，清晰/弱/噪声，参考 Grooby/Zhu）、心/肺、是否异常、信噪。
- **复用公开数据**（已调研，丰富）：用这些**预训练**声音质量/分类模型，再用我们的数据微调，大幅减少标注量：
  - **CirCor DigiScope**（PhysioNet）：大规模心音 PCG，含杂音标注。
  - **ICBHI 2017**：呼吸音基准。
  - **HLS-CMDS**（Mendeley）：临床假人上用 **Littmann CORE** 录的心+肺音 535 条——与我们硬件最接近。
  - AuscultaBase / BUET 多病心音 / ScienceDirect 胸壁肺音数据集 等。

## Phase 2 — 模型架构、融合与分阶段训练（VLA，核心设计）

### 感知和动作怎么融合：不是两个独立模型，而是「共享表征 + 专门化模块」

现有 World-Action / VLA「分开 perception 和 action」分的是**模块**，共享的是**表征**——融合点在共享 latent，不是靠传一个手工坐标。参考：π0（VLM 主干 + action expert，expert 用 attention 读 VLM token）、Octo（共享 trunk + 多 readout head）、GR-2（先视频预测预训练=世界模型，再接动作）。

**我们选 Option：共享主干 + 多任务头 + 分阶段冻结训练**（不是两个独立模型，也不是纯端到端混训）。

> World-Action Model 预训练很重，**先用 VLA**（可复用我们已跑通的 WAM/LingBot-VA，或 OpenVLA/π0/Octo）。World Model 放到 Phase 3 进阶。

### 架构

```
            语言指令 ──┐
RGB-D ─[ViT]──┐        │
本体感知 ──────┤        ▼
力 ─[tokenize]┤   共享 VL 主干 (trunk)         ← 融合发生在这里
音频 ─[encoder]┘        │
                ┌───────┴────────┐
        ┌───────▼──────┐  ┌──────▼─────────┐
        │ 感知头        │  │ 动作头/expert   │
        │ keypoint/热图 │  │ π0式flow或离散  │
        │ →听诊点(+法向)│  │ token,action块  │
        └──────────────┘  └────────────────┘
          ↑网图自动标注训      ↑遥操(+力+音频)训
```

- **融合**：共享 trunk 的 latent。力/音频 tokenize 后进同一 trunk，动作头能 attend。语言条件化 trunk。
- **感知头不丢**：留作安全先验 / 可解释 bootstrap，且让"定位"留在表征层，不退化成脆弱坐标 → 保住 audio 搜索天花板（差异化 A/B）。

### 分阶段训练（用不同数据喂不同部分 + 冻结防遗忘）

```
阶段1  网图自动标注(百万级)  → 训【trunk + 感知头】，动作头 detach
       └ 用海量数据把共享表征/人体理解训扎实
阶段2  遥操数据(百~千级)     → 冻结(或低 LR)trunk，训【动作头】(+力+音频)
       └ 小数据集若混训会冲垮阶段1的表征(灾难性遗忘)，故必须冻
阶段3  解冻联合微调 + 接入音频闭环 / World Model
```

- 不要永久全冻结：trunk 没见过接触/力特征。节奏：**先冻 → 低 LR 联合微调 → 必要时解冻**；中间档用 **LoRA/adapter**（便宜、不破坏原表征）。
- ⚠️ 多数 VLA 只有视觉+proprio，**音频/力编码器需自己加**（音频 token 化是非平凡工作）。
- 动作空间：末端位姿增量/关节，action chunking，定控制频率。

> 一句话：训**一个**模型，分阶段、用不同数据喂不同部分、靠冻结防遗忘；感知与动作在共享表征层融合。

### 感知头：稠密表面对应（已定，2026-05-30）

**不用稀疏关键点，改用稠密 DensePose-IUV 对应**（逐像素预测身体表面坐标 (I,U,V)）。理由：抗噪、抗遮挡、**抗近景/局部视角**（哪怕只拍到躯干，每像素仍有有效表面坐标）。
- **训练标签**：`render_iuv.py` 把 HuMMan 的 SMPL mesh 按 `UV_Processed.mat`(SMPL顶点→IUV) 光栅化成逐像素 IUV 图（已验证；连续UV+全量建议 GPU 用 pytorch3d）。
- **听诊点读出**：推理预测稠密 IUV → 找与目标顶点 (I,U,V) 匹配的像素 → 2D 点（+深度→3D）。点定义见 `humman_label.define_ausc_vertices`。

### 机器人两视角系统（已定）

| 视角 | 位置 | 用途 | 注意 |
|---|---|---|---|
| **第三人称视角**（主感知） | 头顶/机器人头/与桌面平行 | 稳定中景看全/上身 → 跑稠密感知定位听诊点 + **验证机械臂是否到位** | 取景稳，是定位主力 |
| **机械臂腕部视角** | 末端 | 近景接触、局部伺服 | ⚠️ 贴太近会丢上下文→找不到点；**不做全局定位**，靠第三人称+音频闭环 |

→ 感知模型主要跑在**第三人称视角**；腕部视角做接触/局部修正。

### 数据增强 pipeline（算子库 `augment.py`，编排 `datasets/common.augment_once`）

每个 base sample 施加一次**随机组合**(标签[稠密IUV/点]随几何算子同步变换；IUV 用 NEAREST 缩放保 part 离散；出框点 `visible=False` 不计损失)：

- **几何**：`perspective_warp` 透视抖动 **或** `_rotate` 对称小角度 ±8°(二选一) → `hflip`+`LR_SWAP` 水平翻转换 L/R(**仅后背**，前胸心点不对称禁翻) → `crop_to_framing` 取景 **F1远/F2中/F3近**(正方形真像素裁剪，**不补边**，居中于 IUV 躯干质心)。
- **外观**：`clinical_lighting`(色温+单侧检查灯方向光+渐晕+gamma) / `hue_shift` / `specular` / `cast_shadow`。
- **遮挡**：`occlude_medical` → `occlude_robot_arm`(桌面侧装机械臂从**右下方**够向听诊点；电极贴片已弃用——医学位置在合成图上不可靠)。
- **退化**：`sensor_degrade`(运动模糊/高斯模糊/JPEG/传感器噪声)。

**原则**：预训练不管双视角"协同"(那是imitation/控制)，但增强必须覆盖**部署相机的图像统计**。取景缩放(F1→F3)是关键增强——不是怎么拍，是拍哪个部分；低分辨率真实图不再做极近放大，以免破坏皮肤纹理。
**待补缺口**(按重要性)：① **视角俯仰角**(用 HuMMan 10个Kinect多视角，或重渲染) ② **背景替换**(用IUV mask抠人) ③ **深度噪声/空洞**(若 RGB-D) ④ 相机内参/FOV/畸变。

**帧级正面/背面过滤器** `frame_filter.py`(SMPL躯干法向vs相机→front/back/reject)。⚠️ **iPhone 相机固定在受试者正前方→只产出 front(心脏)标签；肺(后背)标签需下 Kinect 后向相机**(10个环绕，~19GB/part，同时可当视角增强)。静态直立帧 IUV 对齐好；动态/蹲弯帧崩且与临床无关，靠此过滤器剔除。

## Phase 3 — 声音闭环 / World Model（核心创新）

- **声音质量评估器**：复用 Grooby 特征 + PhysioNet/ICBHI 预训练 + 我们数据微调。
- **闭环**：声音差 → 在邻域主动微调位置/力（差异化 B）。可用 BO 或学习残差策略。
- **World Model（进阶）**：学**声音随位置/力/呼吸的动力学**，预测声场，规划信息增益最大的下一步（差异化 C/D）。这缓解"每点录音 ~10s"的速度瓶颈——**用预测换实采**，是 World-Action Model 的正当用途。

## Phase 4 — 部署评测

- **指标**：跨体型/坐姿成功率、定位误差、接触力误差、**声音质量**、安全（最大力/碰撞）。
- **基线**：硬编码 / Lopes 几何定点 / Zhu 贝叶斯优化。
- **协议**：固定测试受试者集，盲评声音质量（参考 Zhu 用医学生打分）。
