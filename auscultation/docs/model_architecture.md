# 模型结构（Model Architecture）

系统 = **VLA 动作策略 + 在其之上额外加的感知模块 + 音频驱动的主动搜索(Q)**，共三个模块。各模块输入/输出独立，按下表路由。

## 数据流图

> 两条闭环:**闭环B(每帧)**——病人动/视角变, 感知重算目标点;**闭环A(听诊后)**——音频→Q→在体表流形上挪, 找最优声窗。task(心/肺)选读哪组点。

## ① 感知模块（Perception）—— **双头:稠密 IUV(体表坐标图) + Landmark 热图头(生产读点)**

> **设计:双头(实测演化结论)**。模型有两条并行头:
> 1. **IUV 头**——逐像素稠密 `(I,U,V)`,作为体表参数化坐标图,是 Phase 3 声音闭环/主动探索的统一基底(见下「IUV 作为闭环探索的体表坐标系」)。
> 2. **Landmark 热图头**——每个听诊点一个热图通道,推理 soft-argmax 直接出 `(x,y)`,**生产读点路径**。
>
> **为什么是双头而非原先设想的单头**:最初设计想用「单头 IUV + 固定 `(I,U,V)` 地址反查」一次解决读点 + 探索。但人手金标证明:**IUV-地址法被 HMR2 训练标签锁死在 PCK@10 ≈ 57%**(地址法只能给"正常背"的位置,scoliosis/非典型背崩)。改用**直接受 2D 点监督的 landmark 头**后破到 **96%**(生产模型 `perc_lmh_v4`)。所以读点改由 landmark 头出;**IUV 头保留**(生产训练时冻结,warm-start 自 `perc_v7`),专门承担将来声音闭环要用的体表坐标系职责——两条头各司其职。详见 [`PERCEPTION_STATUS.md`](./PERCEPTION_STATUS.md)、[`landmark_head_and_eval.md`](./landmark_head_and_eval.md)。
>
> **读出是任务条件化的(task-conditioned)**:landmark 头按**固定通道顺序**(后背肺 10 + 前胸心 5 = 15)输出,当前任务(心/肺)只取该任务那组通道。**每组点位仍是自由的设计参数**——点的解剖定义由 SMPL 顶点合成(`define_ausc_vertices`),通道顺序/任务归属在 `tasks.py`,改点=改这两处即可。
>
> **代码落点**:网络 = [`ausc/models/iuv_model.py`](../ausc/models/iuv_model.py)(`DenseIUVModel` + `IUVHead` + `LandmarkHead`);任务→点集+听诊顺序 + landmark 通道顺序在 [`ausc/tasks.py`](../ausc/tasks.py)(`TASKS` / `LANDMARK_ORDER`);点的解剖定义(SMPL 顶点)在 `ausc/humman_label.define_ausc_vertices`。

| 项 | 内容 |
|---|---|
| **角色** | 从第三人称视角**按任务**定位听诊点(心→前胸心脏点 / 肺→后背肺点),并验证机械臂是否到位 |
| **输入** | 第三人称相机 RGB，`[H×W×3]` uint8（**单视角**）；**任务标识**(心/肺,来自语言指令) |
| **主干** | DINOv2 ViT-B/14(冻结) + LoRA(r16/a32) → 特征图 |
| **输出(头 1, IUV)** | 稠密 IUV 图 `[H×W×3]`:逐像素 `(part I∈{0..24,0=背景}, U∈[0,1], V∈[0,1])`。生产推理留作体表坐标图/可视化,**不直接读点** |
| **输出(头 2, Landmark)** | **任务相关听诊点**:`{点名:(x,y,置信)}`(热图 soft-argmax 直接读);区域 `front(心)/back(肺)`;翻转一致性置信门 |
| **输出 3（给VLA, 设计B）** | **目标热图**：把当前目标点画成高斯热图叠在第三人称图上（VLA"看着高亮去"）；+ **3D目标点**（反投影到机器人基座系） |
| **读出方式(生产)** | landmark 头每点一个热图通道 → soft-argmax 出 2D 点 + 结构化读出(R/L 平行、层间距均匀)。**绕开有偏 V 场**(旧 IUV-地址法仅 57%) |
| **任务点集(`ausc/tasks.py` 路由, 可自由定义)** | **心(前胸)**: 5 区 APETM(主动脉/肺动脉/Erb/三尖/二尖, Bates');  **肺(后背)**: 10 点(5 层双侧, V6A 标准, 围肩胛骨)。点解剖定义在 `define_ausc_vertices`, 任务归属+通道顺序在 `tasks.py`; 换点=改这两处, 零标注成本 |
| **训练** | IUV 头:HuMMan/Scoliosis/Synthetic 渲染的稠密 IUV 监督。Landmark 头:纯人手标后背点直接监督(`scripts/train_landmark_human.py`,暖启动+冻结 v7 IUV)+ 自训练放量。详见 [`training.md`](./training.md)、`ausc/training/README.md` |
| **部署** | 只跑第三人称相机；深度仅在推理时几何用于 2D→3D 反投影（传感器测量，**不进网络**） |

## ② 动作策略 VLA（Action）

| 项 | 内容 |
|---|---|
| **角色** | 驱动机械臂：逼近→接触→稳到目标力→听诊→按声音探索；腕部近景伺服，第三人称验证到位 |
| **输入（设计B）** | 第三人称 RGB **(叠目标热图)** ｜ 腕部 RGB ｜ **3D目标点(基座系)** ｜ 本体感知 ｜ 6轴力/力矩 ｜ 音频 ｜ 语言。**不吃原始稠密IUV**（感知已蒸馏成热图+3D点） |
| **结构** | π0 系（Physical Intelligence openpi）为骨干候选：共享视觉-语言 trunk（PaliGemma）+ flow-matching 动作专家；力/音频接 token 编码器并入 |
| **输出** | 动作块（末端 6D 位姿增量 或 关节目标），按控制频率 `f` 输出（action chunking） |
| **训练** | 主从臂遥操作演示，行为克隆；两视角 + 力 + 音频同步录制。**完整训练流程 + 反馈方案见 [`training.md`](./training.md)** |
| **部署** | 两相机 + 力 + 音频全部在线 |

## ③ 音频驱动的主动搜索（Audio-driven Active Search）—— **以学出来的质量模型 Q 为目标**

> **设计原则(关键)**:搜索**不是**模仿医生挪动的轨迹(那只在见过的失败上成立);搜索是**最大化一个学出来的音频质量 Q** 的副产物——因为目标 `max Q` 在**每个状态(含没见过的失败)都有定义**,"声音差→朝声音更好的方向动"在任何状态都自动成立、可泛化。详见下「自发搜索:为什么用 Q 而非模仿」。

**组件 A — 音频质量模型 Q(基石)**

| 项 | 内容 |
|---|---|
| **角色** | 学出来的"评判者":一段听诊音频(+位置/力上下文) → **质量分 + 不确定性** |
| **输入** | 听诊器音频窗口(+ 当前 (I,U,V)、力、呼吸/心动相位) |
| **输出** | `Q∈[0,1]`(听得好不好) + 不确定性 |
| **训练** | 自监督声学代理(SNR / 心动周期可检测性 / S1·S2 峰 / 频谱集中度, **零人工**) + 演示**隐式标签**(医生停留=好、快速离开=差) + 少量医生**偏好/粗标**(A 比 B 好) 校准;可在公开集(PhysioNet 心音 / ICBHI 肺音)预训练 |
| **为何泛化** | Q 学的是"什么声音算好"(感知判断), 天生对没见过的差音频也判"差"→ 触发搜索;比枚举"所有失败的运动恢复"可控得多 |

**组件 B — 优化 Q 的搜索器(三层, 由稳到强)**

| 层 | 做法 | 何时 |
|---|---|---|
| **(a) 部署期显式搜索** | 在 IUV 邻域 `(I,U,V)` 上**最大化 Q**:贝叶斯优化 / MPC / 学出来的残差策略;BC 暖启 | 最安全, 先上 |
| **(b) 残差/离线 RL** | reward = `Q`(或 `ΔQ`), 在 BC 基座上微调策略, 把"低Q→朝高Q动"**内化进策略** | 离线/残差, 防真人风险 |
| **(c) World Model 主动感知** | 学 `(I,U,V)/力/呼吸 → Q` 的动力学, **规划信息增益最大的下一探**(不确定性驱动探索) | 最强, 差异化 C |

**安全/防坑**:硬约束(最大力 / 工作空间 / 搜索半径);不确定性项 + 探索奖励防局部最优;呼吸/心动周期物理先验防 reward hacking(贴太紧噪声小但无信号)。

**输出**:在目标点邻域沿体表解剖方向的微动作 / 下一探点(基座系 3D)。

## 接口、坐标系与两视角（设计B）

### 为什么 VLA 吃"热图+3D点"而非原始 IUV
感知(RGB→IUV, 用人体图训, 无机器人)与 VLA(遥操作演示训, 力/音频/双相机)**训练数据完全不同**。把感知输出**蒸馏成"目标热图(叠第三人称图)+3D目标点"**作为干净接口:VLA"看着高亮去"+ 有度量 goal,且**遥操作数据无需再标 IUV**。灌原始稠密 IUV 会强耦合、且要求机器人演示也带 IUV 标注。

### 两视角的 3D 点怎么同步(关键)
- **一次性手眼标定**:第三人称相机外参、腕部相机外参、机械臂运动学都标定到**同一个机器人基座坐标系**。
- **感知出的目标点**在第三人称相机系 → 用其外参 + 深度反投影 → 变换到**基座系的 3D 点**。VLA/控制都在基座系执行,**两视角不需要各自再算一遍 3D 点**——目标点只在基座系表达一次,腕部相机不负责定位、只做近景闭环伺服。
- **腕部第一视角的作用**:接触前后的**近景视觉伺服**(对准、贴合、微调),它看的是局部细节,不重复第三人称的全局定位。两视角职责不重叠 → 不存在"两个 3D 点要对齐"的问题,只有"一个基座系 3D 点 + 腕部闭环微调"。
- 病人移动 → 感知每帧重算目标点(基座系)→ 闭环更新。

### 骨干选择
- **VLA 骨干 = π0 系(Physical Intelligence, openpi 开源权重)**:PaliGemma 视觉-语言 trunk + flow-matching 动作专家,预训练于大规模机器人数据,原生支持语言指令 + 多相机 + 本体感知;力/音频作额外 token 并入。备选 OpenVLA / GR00T。
- **感知骨干**:DINOv2 ViT-B/14(冻结) + LoRA(r16/a32) + **两条头**(IUV 头 part 分类+U,V 回归;Landmark 热图头出点)。感知与 VLA 两模块分开训,接口=上面的热图+3D点。

### IUV 作为闭环探索的体表坐标系（为什么两条头都留:landmark 头给起点,IUV 头给"往哪挪"）

> **实测演化**:最初想用单头 IUV「一招两用」——既反查地址出点、又当探索坐标系。但金标证明 IUV-地址法**出点**只有 57%(被 HMR2 标签锁死),换 landmark 头才到 96%。所以**出点用 landmark 头**;但**探索坐标系仍非 IUV 不可**,故两条头并存、分工互补。

任务点集(landmark 头给出的那束点)只是**先验/起点**。真正的临床动作是"**边听边找**":某点没听到清楚心音 → 在邻域挪一挪找更好声窗。这一步是 landmark 头给不了、必须靠 IUV 头的地方:

- **Landmark 头**只认识那 15 个点,出点很准,但"往哪挪"没有概念 → 单靠它做探索只能在空间里瞎试,可能挪到手臂/挪出身体。
- **稠密 IUV(IUV 头) = 一整张连续可寻址的体表坐标地图**。"挪一点"变成在**体表流形 (I,U,V) 上搜索**:
  - 沿 **U** 移 = 上下(换相邻肋间);沿 **V** 移 = 绕躯干左右(往胸骨/往外侧)。
  - 每个候选 (I,U,V) → 在预测 IUV 里反查 → 2D 像素 → +深度 → 3D 目标 → VLA 送过去。
  - 探索**始终贴体表**(不飘空中/手臂)、沿**解剖方向**(身体自己的坐标系)。

后续三层闭环(Phase 3,尚未实现)全建在 IUV 头这套坐标系上(对应 README 差异化):
- **B 声音闭环**:声音差 → 在邻域 (I,U,V) 搜更好点。
- **C World Model**:学"声音随 (I,U,V) 怎么变" → 规划信息增益最大的下一点。
- **D 声音自监督定点**:奖励=声音质量 → 系统自学"哪个 (I,U,V) 声音最好",涌现点定义,而非人手定。

语言指令("往下一肋间/再外侧一点")也映射成 (I,U,V) 上的移动。**所以生产虽用 landmark 头出点,IUV 头必须保留作探索坐标系——两条头各管一段:landmark 给起点,IUV 给方向。**

### 自发搜索:为什么用 Q 而非模仿(本系统命门)

纯模仿学到的"搜索"是**记忆一条轨迹**——策略 `π(动作|观测)` 只在演示覆盖的状态附近可靠,**没见过的失败就"无定义"**,不知道往哪找。要让搜索成为**自发、能泛化到没见过失败**的行为,必须把它从"模仿一条轨迹"换成"**优化一个目标函数**":

- **目标 = 最大化学出来的音频质量 Q**(模块③组件A)。`max Q` 在**每个状态(含没见过的失败)都有定义** → "声音差→朝 Q 升高方向动"在任何状态都成立。
- **Q 是评判者不是轨迹**:它学"什么声音算好",对没见过的差音频照样判差 → 触发搜索;判断声音好坏比枚举所有运动恢复可控、可迁移。
- **不确定性驱动探索**:Q 低 / World Model 方差大 → 内在驱动去探索降不确定性,而非"匹配已知坏样本"。
- **BC 被重新定位**:它只负责**安全的接触-力技能 + 合理先验 + 探索暖启**;搜索的泛化性来自 Q-优化层(模块③组件B 三层)。

> 一句话:**把"搜索"从模仿一条轨迹,改成以学出来的 Q 为目标的主动优化——目标函数处处有定义,所以搜索在没见过的失败上也成立。** 完整训练流程见 [`training.md`](./training.md)。

> **部署姿态 = 坐直 / 平躺,看正面胸 或 正面背,不会弯腰**。故训练数据都用直立姿态(合成站/坐 + HuMMan 直立帧),稠密 IUV 标签可靠。
> **scoliosis 决策(纳入,单头一致)**:脊柱侧弯患者腰略歪,SMPL 直脊柱拟合**有小曲率误差**——但听诊容差 1-2cm,**小误差可接受**,故 scoliosis 仍用 **SMPL 拟合的稠密 IUV**,与合成/HuMMan **同一种监督(单头一致)**。⚠️ 但必须**干净重拟合**(正确 person-bbox,而非整图bbox)——旧 `labels_hmr2.pkl` 有个别拟合飘出画面(坏拟合≠小误差),重拟合后误差才落在可接受范围。它的核心价值=**真实裸皮纹理/深肤色**(重点做好)。真脊柱侧弯曲率的极端情况靠合成+HuMMan泛化 + 未来自采临床集。
