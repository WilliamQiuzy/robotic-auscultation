# M0：静止状态恢复专家试验

## 问题与范围

ACT 在实际 R4 接近中持续偏离。固定模型的成对输入试验测到了短时局部响应，
但判断补偿是否足够仍需要同状态、同动态约束的专家参照。下一步先验证可提供恢复标签的专家，再考虑补数据。
本试验不训练新模型，不把专家完成计入 M0 状态模型闭环成功。

## 首轮发现与独立修复

首轮名义点在恢复查询时拒绝：使用瞬时 API `dq≤0.005 rad/s` 判静止，
而已记录的末 240 个物理步中 q 完全不变、PhysX 报告 dq 峰值仍为 0.0082373 rad/s。
无 L3 决策，没有接触成功。原始回合和源码 `f59bd5e` 保留。

首轮三组均已实际结束，3/3 在此门拒绝，接触与保持为零；每组 6,948 个物理步，
28.95 s 仿真时间。原 owner 退出 0、进程组已清理、GPU 已释放。
81 份结果/轨迹/账本在 Mac 逐文件 SHA 验证，目录
`results/ausc_policy/m0_recovery_pilot/`；归档 SHA256：
`ad56977d4c47db510a5354eb502fc568282a25bece03a456c14cacbb6b5ab50d`。
图和汇总在 `results/ausc_policy/m0_recovery_pilot_report/`。
可用 `python -m sim.ausc_policy.recovery_report --evidence EVIDENCE --run-id RUN_ID --output NEW_DIR` 重建。

修订改为检查 13 个连续真实 q/时间戳/指令样本（50 ms）；位置差分速度仍≤0.005，
指令必须一直静止。原始 dq 不改写，同时仍受原 0.175 rad/s 速度上限约束。
这一修订针对“已停车”的判定定义，不改变碰撞、姿态、力、行程或动态安全阈值。
PhysX 速度与位置差分的差别保留为孪生诊断事项，不能外推实机测速等价性。
先用 `m0_recovery_nominal.json` 独立重测名义组，再决定是否继续两侧扰动。
重测 run：`m0-recovery-nominal-position-history-20260929`，源码 `7c58dde`。
新判定对三份旧轨迹的重放结果只是反事实检查，不改变旧回合失败结果。

### 名义组独立实测通过（2026-09-29 15:01 UTC）

上述重测实际完成 26,107 个物理步、2,175 帧 RGB-D，`case_passed=true`。
机械/姿态审计通过；独立重算 ADC/FK/RGB-D 并重放全部 12,524 次监督决策通过，
确认在力带内连续保持 3.0 s，随后撤离和回位。位置差分的 centered 加速度峰值
0.2120 rad/s²、jerk 峰值 14.2136 rad/s³，满足原 2 / 20 门。
报告同时保留未经改写的 API 速度与其他差分定义，不把它们混成相同测量。

查询从实际观测出发，规划耗时 0.9774 s；仿真在查询期间暂停，因此不声称实时控制。
完整恢复提案执行后通过原精细曲线入口检查，原保持及接触阈值未改变。
Linux 从原始相机帧编码完整 108.75 s 录像（20 fps）；视频 SHA256
`222d006935f494baab116b40cb3089630160189e280c6dad987892fc2136d16a`。

这只通过一个无扰动的解析专家回合。M0 状态策略、泛化和训练数据资格仍未通过。
下一组配置 `m0_recovery_perturbed.json` 只复测第三关节 ±0.02 rad；
必须先核实上述实际 owner 正常退出并释放 GPU，再单独启动。

补充诊断：名义组同一静止窗中，`q + 0.05 × API dq` 与当前保持指令的 MAE
约 1.12×10⁻⁶ rad，直接用 q 则为 2.03×10⁻⁴ rad；另外两组也呈同样关系。
报告速度与当前伺服位置差的描述性斜率约 20.1 s⁻¹。
这不能证明求解器内部机制，但说明这里的“API dq 外推”不能直接解释为真实位移速度外推。
原离线基线数值保持不变，后续需把 API dq 外推与历史位置差分外推分别报告，
不能仅用前者给“模型是否拟合运动”下结论。原始刚体 TCP 也核验了静止：
名义窗位移范围为零，两侧扰动组最后 1 秒最大位移范围约 9–11 µm。
这仍是单场景仿真观察，不是实机传感器或动力学辨识。

第一版 oracle 明确只支持 R4、FREE/APPROACH、已脱离人体、实测速度接近零、
连续三个实际指令静止的状态。运动中或 CONTACT/HOLD 状态返回 Abstain，
因此它还不是规格中能支持任意学生状态 DAgger 的完整 oracle。

## 预注册的三组实际试验

独立重建同一批准场景，保持座位、相机、Hall 校准、物理迭代及阈值不变。
每组先真实执行批准的准备路径，再在第三关节加入 0 / +0.02 / −0.02 rad，
实际运动、停车并采集状态；不重置关节、不捏造 RGB-D 或 Hall 观测。
这是人为构造的局部偏离，尚非直接从 ACT 失败轨迹接管，也不表示人体多样性。

查询以实测 q 为规划起点，保留真实指令起点连接，以同一 R4 精确预接触姿态为目标。
复用低肘姿态规划器；新样条每个 240 Hz 指令都重新做 FCL/姿态检查。
速度 ≤0.175 rad/s、加速度 ≤0.5 rad/s²、自由运动 jerk ≤1.5 rad/s³；
自由间隙仍为 3 mm。返回完整专家提案及以当前实测 q 为锚的 H10、50 ms 标签预览。
完整提案在本试验中由专家执行，不冒充 H10/E5 学生在线重查询。

到达后必须通过固定接触曲线的 20 µm / 0.0002 rad 完整位姿入口检查，
再运行原实测解析 L3：Hall/ADC、RGB-D 跟踪及实测关节反馈，4±0.5 N 连续保持 3 s，
原 Hall 5.5 N / PhysX 6 N / 6 mm 硬阈值、接触间隙、撤离及最终回位不变。

## 判定与数据边界

每组记录查询或拒绝原因、实际物理轨迹、所有原始相机/Hall 数据、决策账本，
并执行原机械/低肘审计、独立 ADC/FK/RGB-D 决策重放及实测加速度≤2、jerk≤20检查。
保留所有失败，不改变阈值使其通过。

准备段、恢复段、L3、最终回位有独立角色标记；全部帧目前仍为训练不合格。
即便三组全通过，仍须单独进行原始模态、动作配对、标签导出和恢复数据资格检查。
三组不是专家随机环境≥95%证明；不触发全量 VLA 训练。

配置：`configs/ausc_policy/m0_recovery_pilot.json`。
实际结果以远端新 run 的配置、源码快照、进程退出、case 审计收据为准。

## 后续修复顺序

1. 先完成本批原始RGB-D/Hall/FK重放和查询标签核对，不能把观测账本重放当作原始深度图重放。
2. 单独测定L3可接管的起点区域。现有20µm/0.0002rad是固定曲线的构造前提，不能直接当成学习策略的合理精度要求。
   如需入口对齐，应作为显式、单独验收的L3动作设计；不能暗中接到ACT后再说ACT独自完成了转移。
3. 扩展可查询专家到受限的运动状态：保留真实指令位置、速度、加速度，先验证安全制动及后续路线。
   首先从真实ACT已访问的偏离状态取样；无法保持原限幅和间隙时拒绝，不能重置关节或伪造停车记录。
4. 有了合格恢复标签和已测交接区，再做同预算状态ACT对照与真实Isaac复测。维持原M0门，不因专家通过而跳到全量VLA。

阶段1的单身体诊断不构成M2随机环境专家≥95%门或身份留出泛化验证。当前回合不自动进入任何训练清单。
