## Run the public checks

Use a Python environment outside the capsule. Fixture dependency versions and
the actual execution counts belong to the [bounded CPU receipt](../repro/source45/CPU_FIXTURE_CHECK.json),
not to the historical official/native runtime. Start with the non-Torch profile:

```sh
python3.11 -m venv .venv-source45
.venv-source45/bin/python -m pip install numpy==2.4.6 scipy==1.17.1 pytest==9.2.0 ruckig==0.15.3
.venv-source45/bin/python -B -m unittest demo_tests.test_source45_capsule -v
.venv-source45/bin/python -I -B repro/source45/verify_capsule.py
.venv-source45/bin/python -I -B repro/source45/verify_capsule.py --fixtures
```

`--fixtures` starts an unoptimized `-I -B` child with CUDA hidden and pytest
plugin autoload disabled. Only this capsule and its test-helper directory are
added as project import roots. The child imports all ten entry modules from
their exact capsule paths, runs only the 42 listed original test functions
(parameterizations count as separate cases), prints every skip reason, and
checks loaded project/helper origins. Do not overlay the capsule onto the root,
Source26, Source28 or another checkout with `PYTHONPATH`.

Four additional original test functions require Torch. Three use tiny
**synthetic CPU tensors** to check 54-tensor initialization, numerical probes,
forbidden optimizer import, a fresh AdamW state, and all-40 saved candidate
tensor/prediction bindings. The fourth imports Torch to assert that metadata
admission never calls `torch.load`. They are opt-in; no optimization update or
training run is included:

```sh
# Optional; install a CPU Torch build appropriate for the host, outside the capsule.
.venv-source45/bin/python -I -B repro/source45/verify_capsule.py --fixtures --optional-torch
```

The recorded default run was **130 passed, 2 skipped** from 42 test functions
(132 parameterized cases). After pytest returned, the wrapper checked actual
`sys.modules` entries for `torch` and `torch.*` and observed **zero**; a positive
count fails the default command. The optional extension was **148 passed,
2 skipped** from 46 functions (150 cases), including the default profile, and
the same post-run check observed **1,126 Torch modules**. This records loaded
namespaces at that check, not an all-time import trace. An isolated import
regression verifies that the check detects and rejects an actual imported
namespace in the default mode. Both profiles imported all ten entry modules
from exact capsule paths and confined 140 loaded project/test modules to this
capsule. Six adapter tests and the 97-test public demo regression suite also
passed. These are local synthetic software results; GitHub Actions was not
executed for this addition.

The two pinned Official LeRobot factory checks remain in the default profile
so their original environment skips are visible. An ordinary Torch install does
not satisfy that environment and is not reported as Official ACT integration.
The 20,000-update toy fit test is deliberately **not selected**. The full
historical suites and default root CI are not broadened by this addition.

## How original training and evaluation fit together

The source protocol initializes V9 from authenticated ACT10 selected-step-17,000
tensors, imports no optimizer/scheduler state, and specifies 20,000 **new** AdamW
updates with evaluation every 500 steps. The native/planned/conditional/oracle
batch sizes remain 32/8/8/16, with objective coefficients
0.50/0.125/0.125/0.25. These constants describe a method; the capsule does not
execute or complete that method.

The original guarded sequence separates parent CPU export and collection-only
bootstrap; actual fixed-eight TRAIN collection; full reader/data admission;
frozen observed validation subset; training and all-40 stored-candidate ranking;
selected-model CPU equivalence; actual known-case native evaluation; and only
then any authorized fresh-identity evaluation. Missing/failed/unlaunched slots
remain in their fixed denominators. A positive collection label prefix is not
a full H20 label window, a trained model or a benchmark result.

The policy is prescribed-goal, state17/H2 neural ACT L2 with H20/E10 and analytic
Hall-feedback L3. RGB-D and Hall recordings are not neural multimodal inputs.
This capsule makes no audio, VLA, hardware, all-ten-target, unseen-pose,
fresh-identity, usable-model or clinical claim. Actual experiment evidence is
reported separately in the existing [ACT11 data-integrity report](drafts/act-recovery-20261106.html#iteration11-data-integrity)
and its [public evidence record](drafts/evidence/act11-source44-data-integrity-20261108.public.json);
none of that evidence is generated by these fixture runs.
