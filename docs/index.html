01 / THE LEARNING LOOP

Teach the approach.
Measure the contact.

The current baseline learns collision-checked approach trajectories. A local controller handles force, dwell time and release. Every completed episode must return home.

  1. 01

    Build the scene

    OpenArm, spring-loaded stethoscope, seated body and the approved RGB-D view.

  2. 02

    Query the expert

    Plan from the current state; retain actual commands, measured motion and contact.

  3. 03

    Export valid windows

    Filter by phase and ownership. Split by body identity before fitting normalization.

  4. 04

    Train official ACT

    Predict 20 actions. Execute the first 10, observe again, then replan.

  5. 05

    Run closed loop

    Score the actual approach, contact, hold, withdrawal and return—not just action error.

RELEASED ACT BASELINE

A small, explicit control baseline.

Official LeRobot ACT, 2.66M parameters, no VAE. Two frames of state17 become 34 input features; raw joint targets use one fixed origin per action block.

state17 × 2H20 / E10FP32TRAIN-only normalization

The published ACT uses state and target geometry. RGB-D and Hall are recorded; Hall drives the analytic contact controller. This ACT is not a multimodal VLA, and simulated audio is not used.

A COMPARISON WORTH RUNNING

Does reasoning improve completion and recovery?

Compare the same scenes, targets, local executor and physical gates: analytic expert, ACT + contact controller, then Astra + local skills. Report model calls, interventions, wall time and API cost alongside success.

Cloud reasoning is outside the force loop. Astranomy reports substantial inference latency in manipulation; our contact controller must keep running locally between decisions.
